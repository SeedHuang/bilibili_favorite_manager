# 夹子三分类 + 规则并入整理页 — 设计文档

日期:2026-09-21
状态:已与用户确认(澄清阶段逐项拍板,见文末决策记录)

## 背景与目标

规则生成(`/rules` 顶栏的夹子方案)已经跑通,接下来是把"整理"真正落地。本设计解决四件事:

1. **页面合并**:`/rules` 的职责并入整理页 —— 规则树的每一行本来就是夹子,"按规则整理"和"按人的意愿整理"是同一个页面的两种动作,分两个 tab 没有道理。
2. **夹子三分类**:默认收藏夹 / 人类建立 / AI 建立,三类夹子的权限与成员纪律各不相同,数据库必须能区分"谁建的"(现状分不出)。
3. **删除语义**:删夹子 = 删容器 + 容器背后的规则,**不是删视频**。删之前确保条目不会无家可归(安全网)。
4. **修正两处既有缺陷**:关键词录入用下拉 Select 导致"选项里没有的词就填不了";采纳草稿后规则行不自动展开。

## 1. 概念模型与不变量

三类夹子,各有一条铁律:

| 类型 | 标记 | AI 能做的 | 成员纪律 |
|---|---|---|---|
| 默认收藏夹 | 🔒(现有 `isLockedFolder`) | 什么都不许:改名/删除/合并源/加规则/进提案 | 用户手动管理;条目落进主题夹子时移出(现状语义,保持) |
| 人类夹子 | 无标记 = 人类(存量默认) | **不可合并、不可删除**;可推荐规则 | **只加不清**:程序化写入只插入缺失成员,永不清出。离开只有一条路 —— 用户手动移出 |
| AI 夹子 | 侧表标记(`work_ai_folders`) | 可提合并/删除草稿(采纳才执行) | **精确对账**:成员恒等于规则命中集。手动移出被禁(移了下次对账也会回来,不如不让移)。成员的唯一入口是它的规则 |

推论(都是上面三条的必然结果,不是新规则):

- **AI 夹子必须恒有 ≥1 条规则** —— 采纳时建夹 + 写规则同事务,规则 UI 只读,不变量自然成立。
- **AI 归类结论只写人类夹子** —— 写 AI 夹子的条目若不被规则命中,下次对账必被清出,自相矛盾。想让某条进 AI 夹子,正路是采纳一条规则建议。
- **同步永不直接碰工作副本成员** —— 同步只写快照(现状),新条目要等整理才按规则进入。"同步带进来再清出"实际表现为"清出只发生在规则改变后的整理时"。

## 2. 数据模型(全部 `CREATE TABLE IF NOT EXISTS`,零 ALTER)

```sql
-- AI 创建标记:有行 = AI 夹子,没行 = 人类夹子。
-- 照 work_folder_rules 的老套路开侧表,不动 work_folders。
-- 保守默认:存量夹子没有记录 = 人类夹子;标记只写不改,无手动改标入口(用户拍板)。
CREATE TABLE IF NOT EXISTS work_ai_folders (
  folder_id  INTEGER PRIMARY KEY REFERENCES work_folders(id) ON DELETE CASCADE,
  created_at INTEGER NOT NULL
);

-- 审查草稿(与生成草稿分表 → 两类草稿互不误伤自动成立:生成只清自己的表)。
CREATE TABLE IF NOT EXISTS review_drafts (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  kind            TEXT NOT NULL,      -- 'rule' | 'merge' | 'delete'
  folder_id       INTEGER NOT NULL,   -- 目标夹子(merge 时 = 被并掉的源)
  into_id         INTEGER,            -- 仅 merge:并入的目标
  conditions_json TEXT,               -- 仅 rule / merge(并集)
  reason          TEXT,
  status          TEXT NOT NULL,      -- 'pending' | 'adopted' | 'discarded'
  created_at      INTEGER NOT NULL
);
```

- 生成草稿表 `folder_proposal_folders` / 方案头 `folder_proposals` **不动**,生成逻辑一行不改。
- 运行态(状态 + 日志 + 中止)照抄 `proposalRun` / `folder_proposals` 的既有模式,新增 `reviewRun`。
- 采纳 AI 夹子时在 `work_ai_folders` 插一行,与 `createFolder` + `saveRule` 同事务。

## 3. 成员资格写入器(本设计的核心,一个函数)

所有程序化成员变更收口到**唯一函数**(`workbench.ts` 新增),三条路径 —— 整理对账、AI 归类应用、采纳填充 —— 全部走它:

```
writeMembership(itemId, targetFolderIds):
  对每个目标夹子:
    AI 夹子   → 不直接写,报错(AI 夹子只能由 reconcile 写)
    人类夹子  → INSERT OR IGNORE(只加)
    默认夹    → 正常写
  对"条目当前在、但不在目标集"的夹子:
    默认夹    → 若条目落进了至少一个主题夹子 → 移出(现状语义)
    人类夹子  → 跳过(只加不清 —— 红线在这里落地,一个 if)
    AI 夹子   → 只能由 reconcile 触发(写入器不碰)
```

- `reconcileAiFolder(folderId)`:算规则命中集,与现有成员比对 → 缺的补进,多的逐条走**安全网**(§4)后移出。
- AI 归类应用路由(`routes.ts` 的 apply)从 `assignItems` 切到写入器;目标集里出现 AI 夹子 id 直接过滤掉(洞 4)。
- 为什么收口:现状 `assignItems` 是"先清空条目全部归属再按结论插入",在新模型下会把条目从人类夹子清出去 —— 踩红线。三条写入路径各写各的迟早分叉,一个函数把三条纪律编码在一处,分叉在结构上不可能。

## 4. 安全网(字面版,用户拍板洞 6 = A)

程序化移出成员资格的**每个**落点都先查默认收藏夹:

- **AI 夹子对账清出** → 逐条查:不在默认夹就补进,**哪怕它在别的夹子里活着**(字面版)。
- **删夹子**(人的手动删、AI 提案删,一律)→ 先对全体成员补默认夹,再删容器 + 规则(`ON DELETE CASCADE` 带走规则)。
  **这条取代 m4b 的"只能删空夹"红线** —— 非空夹子可以删了,成员由安全网兜住;"删夹子不删视频"正是安全网存在的意义。实现时必须移除 `deleteFolder` 里的空夹检查,否则安全网对手动删除永远不触发。
- **合并不触发** —— 成员有新家;但并入 AI 夹子后,新夹子对账清出不命中者 → 安全网接住。
- **人手动移出不触发** —— "未归类"是合法状态,那是人的明确意图。

已知代价(用户拍板接受):删一个成员同时在 B 夹里的夹子,会给默认夹多塞一份,默认夹会因此变大。实现上安全网是写入器旁边的一个小函数,不是散在各路由的 if。

## 5. 三个动作与按钮逻辑

| 按钮 | 位置 | 消费勾选 | 行为 |
|---|---|---|---|
| **生成方案** | 顶栏(现有) | 否 | 全库扫 → **新** AI 夹子草稿。逻辑零改动 |
| **审查勾选的夹子 (N)** | 顶栏(新,0 勾置灰) | 是 | 一次 LLM 调用:人类夹子按共现指标出**规则草稿**;AI 夹子出**规则/合并/删除**草稿。运行中被勾选的夹子就地展开规则区 |
| **整理** | 显式化(新) | 是(0 勾置灰,**无全库回退** —— 想全库就全选) | 对勾选夹子兑现成员关系:AI 夹子精确对账、人类夹子只加不清。**纯本地计算,不调 LLM、不花钱** —— 它执行的是已经存在的规则与成员,不是重新归类;Pass 2 归类不接进这个按钮 |

按钮状态表(唯一真互斥 + 可用性 gating):

| 状态 | 生成方案 | 审查勾选 | 整理 |
|---|---|---|---|
| 空闲,勾选 0 个 | 可用 | 置灰 | 置灰 |
| 空闲,勾选 ≥1 | 可用 | 可用,显示 (N) | 可用,显示 (N) |
| 生成运行中 | 运行态 | 置灰 | 置灰 |
| 审查运行中 | 置灰 | 运行态 | 置灰 |
| 整理运行中 | 置灰 | 置灰 | 运行态 |

- **同一时刻只许一个动作跑**(共享运行锁)。原因:生成开跑会清生成草稿(`startProposal` 现有行为),并发跑会互相毁掉对方产出。
- **整理没有"没勾 = 全库"的回退** —— 没勾反而动作最大,是危险方向;想全库整理就全选。
- 生成跑之前若草稿区有待处理草稿,沿用现有确认弹窗("未采纳的旧草稿会被覆盖")。

**流程闭环**:审查 → 「全部采纳」(只作用于 rule 草稿;merge/delete 破坏性,必须逐条确认,不许批量)→ **自动对勾选范围跑一次整理**(全自动不弹待确认,结果可见 —— 符合"自动优先于审阅闸门"的既有约定)。

## 6. 草稿体系

一份草稿区(整理页顶部),两类来源混合显示,带 kind 标签:

| | 生成草稿(现有表) | 审查草稿(新表) |
|---|---|---|
| 产出自 | 生成方案 | 审查勾选的夹子 |
| 内容 | 新 AI 夹子(名字 + 规则 + 命中数) | rule / merge / delete 三种 |
| 单条操作 | 采纳 / 改名采纳 / 丢弃 | 同左(merge 采纳 = `mergeFolders` + **写规则并集**,洞 5;delete 采纳 = 安全网 + `deleteFolder`) |
| 批量操作 | 全部采纳 / **全部丢弃**(新增,与全部采纳并列同款) | 全部采纳(只作用 rule 草稿) |

- 规则草稿采纳 = 追加条件(origin 'ai'),过 `validateSuggestion` 自证 —— 打不中证据整条丢(现有纪律照搬)。
- **规则并集是 AI 夹子合并的必要部分,手动路径同样适用**:不写并集,源夹子规则随容器 CASCADE 消失,源成员里不命中目标规则的下次对账全被清出 —— "合并"悄悄变成"合并 + 驱逐"。所以 `mergeFolders` 对 AI 夹子必须收规则并集(源有规则而目标没有的,合并进目标规则,origin 取 'ai'),而不是只挂在 AI 草稿上;人类夹子合并不受此约束(只加不清,无驱逐问题)。
- 未采纳的草稿**不在树里**(没有 checkbox),从结构上堵死"勾选一个未采纳草稿"的状态。

## 7. 界面重组

- **`/rules` 顶级 tab 删除**,导航收为:总览 · 标签 · 整理 · 授权。规则从此住在树的夹子行里:每行可展开规则区 —— 人类夹子**可编辑**,AI 夹子**只读**(建议采纳/改一下是唯一写入通道,origin 记 'ai'),默认夹没有规则区。
- 夹子行新增:来源图标(🤖 = AI 建 / ✎ = 用户建)、checkbox(默认夹除外,它不参与审查/整理)。**采纳的 AI 夹子默认勾上**(全部采纳 → 自动整理的链路不能断在自己手里),人类夹子默认不勾。
- 关键词录入:「标题含」等条件从下拉 Select 改为 **tag 输入框**(打字 + 逗号成 chip、点 x 删、去重、自由录入不限选项)—— 修掉"下拉没有的词就填不了"的缺陷。
- 修采纳后规则行不展开的 bug:展开状态由树统一管理,采纳后定位展开该行。
- 原「跳 /rules?folder=」改为就地展开;归类产生的 AI 建议栏迁到整理页。

## 8. 测试(不变量优先)

| 测什么 | 守什么 |
|---|---|
| 写入器:人类夹子存量在整理 / AI 应用 / 采纳后**原样保留** | 红线本体("只加不清") |
| 写入器:目标集含 AI 夹子 id → 拒绝 | 洞 4(AI 夹子唯一入口是规则) |
| reconcile:多则清(走安全网)、缺则补;无规则夹子不存在 | AI 夹子定义 |
| 安全网:程序化清出 / 删夹子时不在默认夹 → 补进(哪怕有别家);**手动移出不补** | 洞 6 字面版 |
| AI 提案删 / 并人类夹子或默认夹 → 拒绝 | 三分类红线 |
| merge AI 草稿采纳后规则 = 并集;**手动合并 AI 夹子同样产出并集** | 洞 5(合并不驱逐,两条路径都守) |
| 生成不清审查草稿、审查不清生成草稿 | 洞 8(分表) |
| 全部采纳(rule)→ 自动整理勾选范围 | 流程闭环 |
| 无标记夹子按人类夹子对待 | 洞 9 保守默认 |
| AI 夹子条目行无「移出」入口(服务端也拒) | 精确对账的推论 |
| 采纳 AI 夹子 = 建夹 + 规则 + AI 标记同事务 | 不变量"AI 夹子恒有规则" |

**只手动验证**:真机上勾选 → 审查 → 全部采纳 → 自动整理的整链路手感;草稿区两类草稿混排的可读性;tag 输入框的录入手感。

## 9. 不在这一轮

- 手动改 AI/人类标记(拍板:不变,存量 = 人类)
- AI 夹子规则在树里直接编辑(只读,走建议通道)
- 人类夹子合并时的规则合并(现状:源规则随容器删;人类夹子只加不清,无驱逐问题,不动)
- B 站远端安全网(写回 M5 时自然兑现成远端操作)
- 夹子顺序(sort_order,`m4b` 已有结论:快照没抓顺序,做了也不通)
