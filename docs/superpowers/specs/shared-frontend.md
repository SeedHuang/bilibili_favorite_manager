## 11. 前端

### 11.1 设计从哪里来(约束,不是偏好)

设计方向由这几条事实推出,不是拍脑袋:

- **内容是彩色缩略图** —— 3000 张视频封面本身就是一堵色彩墙
- **核心动作是「移动」** —— 条目从夹子 A 到夹子 B
- **核心交互是「协商」** —— AI 提案 vs 你的修改("建议权"的视觉化)
- **核心风险是「不可撤销」** —— 删失效内容撤不回来
- **用户是一个人**(技术背景),本地工具,不需要营销感

### 11.2 五条设计原则

1. **封面是唯一的彩色** —— chrome 全程中性,让 3000 张封面去承担所有色彩
2. **颜色编码归属权** —— 中性=你的数据,粉色=AI 的提案,红色=不可撤销,绿色=已完成。
   **颜色是信息,不是装饰。** 看一眼颜色就知道「这是谁的主意」—— 直接服务于「建议模式」
3. **数量永远可见** —— 每个夹子、每个状态都带数字,一律 tabular numerals
4. **危险在空间上隔离** —— 删失效内容单独一块,永不与常规操作混排
5. **动效只服务于状态变化** —— 不做入场动画。动效回答的是「刚才发生了什么变化」

### 11.3 设计令牌

**调色板**(冷酷纸面 + 单一热色)

| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#F6F7F9` | 页面底 |
| `--surface` | `#FFFFFF` | 内容面 |
| `--ink` | `#17191E` | 主文字(冷调墨) |
| `--ink-soft` | `#666E7A` | 次要文字 |
| `--rule` | `#E4E7EC` | 发丝分隔线 |
| `--accent` | `#FB7299` | **bilibili 粉 —— 唯一的热色** |

状态色(语义,非调色板核心):`--danger #CF4B4B`(不可撤销)、`--ok #2E9E6B`(已完成)、
`--warn #C98A2E`(待处理)。

**字体**

| 用途 | 字体 |
|---|---|
| 中文 | 系统栈:`PingFang SC` / `Microsoft YaHei` / `Noto Sans SC` |
| 拉丁 + 数字 | `IBM Plex Sans`,数字一律 `font-variant-numeric: tabular-nums` |

字号阶:12 / 13 / 15 / 18 / 24 / 32。信息密度高,基准 13–14。

`ponytail: 中文用系统栈,不加载 CJK webfont(动辄数 MB)。字体性格来自字重/字号/间距/数字对齐,
不来自 display face。要换 CJK webfont 再说。`

**形状**:不统一圆角。行/表格 0,卡片 4px,浮层 6px —— 按层级区分,不是"全站一个 4px"。
**不用卡片装列表**:条目列表是密集行 + 发丝线,数据工具该长得像表格。

### 11.6 图标策略

三层分工,**不要混用**:

| 层 | 包 | 职责 |
|---|---|---|
| 静态图标 | `lucide-react` | 提供图标路径数据。绝大多数图标用这层 |
| 状态形变 | `morphicons/react` | 只负责「A 形变到 B」的弹簧动画 |
| ❌ | `@ant-design/icons` | **主动不用**,避免三套图标打架 |

`morphicons/react` 是 `morphicons` 包的**子路径导出**(已实证 tarball 内含 `dist/react.js`),
导出 `MorphIcon` 组件。它的 `IconInput` 类型是 `IconNode | string` ——
**它是形变引擎,不是图标集**,必须由 lucide 之类的描边图标集提供路径数据。
仅支持描边图标(填充类无法形变)。peer dep `react >= 18`,零运行时依赖。

**morphicons 只用在状态切换上**(形变真正有信息量的时刻):

| 场景 | 形变 |
|---|---|
| 同步 | ⟳ → ✓ |
| 收藏状态 | ♡ → ♥ |
| AI 归类中 | ◌ → ✓ |
| 侧栏开关 | ☰ → ✕ |

静态图标夹子、标签、按钮一律直接 lucide。给每个图标包一层 morphicons 是纯浪费。
`ponytail: morphicons 只用于状态切换;静态图标用 lucide 直出。`

### 11.7 授权流程(cookie)

**产品里永远不让用户碰文件。** `.env` 仅是 M1 手工探针的 dev 权宜之计,产品路径不走它。

```
/settings → bilibili 授权
┌────────────────────────────────────────────────────────┐
│  粘贴你的 Cookie                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │ SESSDATA=xxx; bili_jct=yyy; ...                  │  │
│  └──────────────────────────────────────────────────┘  │
│  浏览器 F12 → Network → 任意请求 → Copy as cURL,       │
│  整段粘进来即可,自动提取需要的字段。                      │
│                                                        │
│  [ 验证并保存 ]                                         │
└────────────────────────────────────────────────────────┘
         ↓ 验证成功后
┌────────────────────────────────────────────────────────┐
│  ✓ 已连接  (●) 头像  用户名  UID:12345                  │
│    最后验证:2 分钟前        [ 重新授权 ]                 │
└────────────────────────────────────────────────────────┘
```

三条硬性设计:

1. **粘贴整段,不是分开填两个框** —— 用户最容易犯的错就是从 cookie 表里复制错字段。
   直接支持粘贴 `Copy as cURL` 的整段内容,后端正则提取 `SESSDATA` / `bili_jct` / `buvid3`。
2. **保存前必须验证** —— 调 `nav` 拉出头像 + 用户名 + UID 给用户确认"是对的那个号"。
   失败要说清楚是格式错、还是已过期。
3. **过期不用重写文件** —— 存 SQLite `settings` 表。启动时自动检查授权,
   失效则顶部出条幅「登录已失效 → 重新授权」,一键直达。重新授权 = 一次粘贴。

**不做扫码登录** —— 扫码要调二维码接口 + 轮询,多两个风控暴露面,而 cookie 有效期有几个月。
`ponytail: 手动 cookie,不做扫码;额外接口 = 额外风控面,收益不值。`

**`.env` 已删除。** M1 的手工探针(`npm run probe:live`)改为**运行时交互式粘贴**
cookie —— 支持贴整段 cookie 或 `Copy as cURL` 的内容,自动提取字段,不落盘、不读文件。
这样连开发期都不需要用户碰文件(C10 的好处顺带覆盖了 dev 路径)。

M2 建好 `settings` 表后,探针可改为复用同一份存储,但交互式粘贴作为"无依赖的兜底"保留。

### 11.8 前端实现要点

- `.umirc.ts` 设 `antd: false` 关掉内置 antd4,自装 antd 5
- 数据获取用 `@umijs/max` 内置的 `useRequest`
- **进度推送走 SSE**(同步进度 / 归类进度 / 执行进度),Fastify 原生支持,比轮询干净
- dev 时 umi 代理 `/api` → `127.0.0.1:3001`
- 设计令牌用 CSS 自定义属性落地(`--paper` 等),antd 5 的 ConfigProvider theme 只覆盖
  必要项(主色 = `--accent`),其余走自定义 class
- 无障碍底线:键盘可见焦点、`prefers-reduced-motion` 下 morphicons 降级为瞬时切换
  (`MorphIcon` 的 `reducedMotion="user"`)、对比度达标

### 11.9 AI 助手(常驻悬浮,2026-09-15)

**位置**:全站右下角,固定悬浮,**不在任何 tab 内**。

**视觉(沿用 CP2077 HUD 调性)**:青色发光描边的像素风形象 + morphicons 状态形变(默认/激活/工作中)。
**形象**:从社区免费素材中挑选(itch.io 搜 `pixel art ai assistant` / `cyberpunk hud robot`),
**当前不写死,留个 `<AIAssistantIcon>` 组件插槽**,形象后期注入。

**入口动作**:**默认动作「整理文件夹」** —— 跑 §9.0 完整流程。
**会话能力**:
- **历史可续**:对话存 `sessions` + `session_messages`,侧栏展示过往会话列表
- **上下文超限处理**:Vercel AI SDK 不管上下文,我们自己管 —— 加载时拼
  「最近 N 轮原文 + 旧轮滚动摘要 + 当前结构化状态(体系 + 偏好)」,超限自动压缩最旧 1/3
- 流式输出(打字机效果),与现有 HUD 风格一致

**与 `/curator` 的关系**:**手动编辑** 在 `/curator` 页面,AI 整理 **在任何页面调悬浮图标**,两条路不冲突,可同时进行。
