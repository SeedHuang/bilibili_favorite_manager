- [ ] **Step 3: 实现**

proposal.ts:

```ts
// 模块级运行态(照 tagRoutes currentRun 模式):logs 绑当前 run,重启清空
export const proposalRun = {
  running: false,
  logs: [] as { ts: number; level: 'info' | 'warn' | 'error'; text: string }[],
};
const pushLog = (level: 'info' | 'warn' | 'error', text: string) => {
  proposalRun.logs.push({ ts: Date.now(), level, text });
};
```

runGeneration 改造:
- 签名加 `opts: { signal?: AbortSignal } = {}`
- 开头:`proposalRun.running = true; proposalRun.logs = [];` + pushLog('info', '开始生成方案(档位 L)')
- 关键节点 pushLog:备料完成(词数/共现对数)、裁判各丢弃一条(沿用现有 log.event 的 message,pushLog 同文)、落库成功(`方案就绪:N 个草稿夹子`)、失败(message)
- `complete({...})` 加 `...(opts.signal ? { abortSignal: opts.signal } : {})`(provider complete 已支持 abortSignal,tagRoutes 里 controller.abort 的中断会以 AbortError 抛出)
- catch 分支:若 `opts.signal?.aborted`,pushLog('warn', '已中止 —— 已生成的草稿不保留'),错误消息写 '已中止';仍回 idle(现有 catch 逻辑)
- finally:`proposalRun.running = false;`

proposalRoutes.ts:
- 模块级 `let currentController: AbortController | null = null;`
- generate 路由:创建 controller 传入;`currentController = controller`
- 新路由:

```ts
app.post('/api/proposals/abort', async (_req, reply) => {
  if (!proposalRun.running || !currentController) {
    return reply.code(409).send({ ok: false, reason: '没有正在进行的生成' });
  }
  currentController.abort();
  return { ok: true };
});
```

- current 路由返回追加 `logs: proposalRun.logs`
